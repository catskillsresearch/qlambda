Answering Chris Heun: ωQVA, D∞, and Q

Feedback: “I can’t actually see a definition of the main characters — the category ωQVA, the object D∞, or the monad Q.” The Lean formalization defines all three; the original paper spread them across later sections. This page states them in one place, then records the revised implementation plan (semantic product first, IBM Composer target). No MathJax; Unicode and code names only.

Short reply (shareable)

Thanks — that gap is what the revision fixes. In Lean the three objects are defined; we will put them upfront in the paper. Intended reading:

1. ωQVA (not a hand-wavy “category” label)

Objects are continuous lattices D such that the identity Scott map id : D → D is the directed supremum of an increasing sequence of approximants, each Q-factorable: it factors through a finite product of Loewner spectrahedra S≤1(Md) (sub-normalized density matrices), with finite separation between approximants.

Lean: typeclass IsOmegaQVA D in QLambda/OmegaQVA.lean. Closure under products, retracts, countable products, function spaces, and the quantum power Q(D) is proved there and in QLambda/QuantumPower.lean.

Categorical gloss (optional): objects = such lattices; morphisms = Scott-continuous maps (Scott1972 library). We do not axiomatize a separate category sheet—the proof artifact is a subcategory of continuous lattices carved out by IsOmegaQVA.

2. D∞ (the value domain)

Fix a quantum power model M (see Q below) and an initial pointed ωQVA domain D₀ with a bonding projection

j₀ : D₀ ◃ [D₀ → Q(D₀)]

Define the tower Dn+1 = [Dn → Q(Dn)] with bonding maps from Scott’s function-space tower. Then

D∞ = QDInf M D₀ j₀

the inverse limit of that tower (compatible tuples (x₀, x₁, …) with xn+1 = jn xn). Capstone (maps qEmbInfInf / qProjInfInf in QLambda/QuantumDomainEquation.lean):

D∞ ≅ [D∞ → Q(D∞)]   (in ωQVA)

Canonical instance: D₀ = PUnit, theorem canonical_omegaQVA_quantum_domain_equation_solved. Term values live here; interpreter SemanticValue is this solved carrier.

3. Q (computation monad — parameter + concrete instance)

Abstractly, Q is any endofunctor on complete lattices satisfying IsQuantumPowerModel:

  • Q(D) is a complete lattice when D is;
  • Q is functorial on Scott maps, order-enriched, locally continuous on monotone ℕ-chains;
  • ωQVA closure: D ∈ ωQVA ⇒ Q(D) ∈ ωQVA.

Computations are elements of Q(D∞), not of D∞. Call-by-value Kleisli arrows are [D∞ → Q(D∞)] — exactly what the domain equation targets.

For the monad, add IsQuantumMonad (QLambda/Monad.lean): Scott-continuous unit : D → Q(D) and bind with the usual laws.

One closed-form instance (fixed register dimension n):

Qn(D) = [[D → Rn] → Rn]

where Rn is the rounded TT result theory (TTResult n; Lean TTContinuationPower n D in QLambda/TTContinuationMonad.lean). Finite quantum instruments embed into these continuations via QLambda/QuantumInstrument.lean and the TT embedding — Q is not “the space of all density matrices.”

Second semantic layer (revision scope)

We do not claim one opaque monad Q already is “the category of quantum circuits.” Circuits get a compositional classical–quantum denotation

⟦C⟧ ∈ DCQ

(CP maps, instruments, classical store). Programs use ⟦M⟧ ∈ Q(D∞) with ⟦emit I⟧ = ⟦I⟧ on shared instruction semantics. Capstone for compilation:

⟦compile(M)⟧ = ⟦M⟧

in DCQ (plus scheduler/selector parameters for ⊓ and □). Composer/OpenQASM graphs are export syntax, not the definition of meaning.

Revised implementation plan

Final goal: one compositional classical–quantum denotational semantics for qλ and IBM Quantum Composer, with machine-checked compile/embed preservation — domain theory (ωQVA, D∞, Q) for the λ-calculus layer and DCQ for circuits, meeting at emit.

Fixed scope

  • One versioned IBM Quantum Composer / OpenQASM circuit (not full Qiskit Python).
  • Opaque qubit handles + separate quantum/classical store; no cloning via copy.
  • Context-free emit-kernel qλ: λ, application, ⊕p, ⊓, □, emit I.
  • Choices: ⊕p → ancilla coin; ⊓ → compiler scheduler; □ → external classical selector.
  • Ideal, finite-register, noise-free semantics; no equality with noisy QPU behavior.

Architecture (two syntax layers, one CQ semantics)

  • qλ term M → CBV denotation ⟦M⟧ (Scott values + Q(D∞) + emit steps).
  • Composer circuit C → compositional ⟦C⟧ ∈ DCQ.
  • compile (with scheduler) and embed (total on AST).
  • OpenQASM — presentation only, derived from AST.

Implementation stages

  1. Heunen definition pack (stage 0). Docs + arxiv.md skeleton; no capstone restatement until the three definitions and crosswalk exist.
  2. CQ semantic domain. Register-indexed instrument monad + classical store as authoritative circuit meaning; document graphs/OpenQASM as export only.
  3. Composer denotation (primary). QLambda/Composer/Denotation.lean: compositional ⟦·⟧ on frozen Composer AST (gates, measure, reset, control flow; bounded loops initially). Reuse Choi/Kraus from QuantumInstrument.lean.
  4. Source denotation. CBV qλ with ⟦emit I⟧ = ⟦I⟧; ⊕ / ⊓ / □ at semantic level (ancilla, scheduler, external selector).
  5. Freeze Composer AST. Versioned syntax + fixtures from representative Composer circuits (QLambda/Composer/Syntax.lean).
  6. Source language. Emit-kernel grammar + circuit well-formedness judgment (QLambda/Source/Syntax.lean); legacy QLambda/Syntax.lean untouched until migration proofs pass.
  7. Translations. Compiler/ToComposer.lean and Compiler/FromComposer.lean; correctness = denotation equality in DCQ, not graph isomorphism as the main claim.
  8. Theorem ladder. Compositionality of circuit ⟦·⟧; choice compilation lemmas; ⟦compile(M)⟧ = ⟦M⟧; embed ∘ compile ≈ id on the fragment; round-trip modulo normalization.
  9. Paper repair (after proofs). Section 2 and tables: lead with definitions of ωQVA, D∞, Q, then DCQ and Composer correspondence; separate ideal semantics from backend noise.

Repository boundary

  • Reuse: Scott1972, IsOmegaQVA, domain equation, QuantumInstrument, Interp/Soundness/choice patterns, TT stack for concrete Qn.
  • Supersede: one-qubit inline HardwareOperational story and adequacy capstones tied to 2×2 density-in-value primitives.
  • Freeze initially: Palomar challenge metadata until new Composer theorems replace the registered capstone narrative.

Feasibility

  • In scope: total embed Composer → qλ; compile terminating well-formed programs to one circuit; denotation preservation in ideal finite-register semantics.
  • Later: full Scott-complete quantum powerdomain for demonic ⊓.
  • Out of scope: exact bijection on all untyped λ-terms; arbitrary Python Qiskit; predicting noisy runs.
